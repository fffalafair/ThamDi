## 🔵 P1 — AI + Eval

### P1-01 · ระบบ A: LLM เขียน SQL ครั้งเดียว — 23–24 ต.ค. · M
**ไฟล์:** `agent/loop.py`, สร้างใหม่ `agent/prompts.py`, `scripts/ask.py`
**ทำอย่างไร**
1. ใน `prompts.py` เขียน system prompt: บอกบทบาท, ให้ตอบเป็น SQL ของ DuckDB อย่างเดียว, ใส่ schema ทุกตาราง (จาก `describe_table`)
2. ใน `loop.py` ทำฟังก์ชัน `answer_system_a(con, question)`:
   - สร้าง schema text → เรียก `llm.chat()` → ดึง SQL ออกจากคำตอบ (ตัด ```sql ออก)
   - เรียก `tools.run_sql()` → ได้ผล
   - เรียก LLM อีกรอบให้สรุปผลเป็นภาษาไทย
   - คืนค่าเป็น `ChatResponse` (ใส่ `steps` ทุกขั้น)
3. ใน `scripts/ask.py`: `python scripts/ask.py --db data/datasets/demo.duckdb "มีลูกค้ากี่คน"` พิมพ์คำตอบ + SQL

**ข้อควรระวัง:** ส่ง schema เป็น "ข้อมูล" แยกจากคำสั่งชัดเจน เช่นครอบด้วย `<schema>...</schema>` เพื่อกัน prompt injection จากชื่อคอลัมน์หรือค่าในเซลล์

**เสร็จเมื่อ:** ถาม 5 คำถามจาก `questions.jsonl` ผ่าน CLI ตอบถูกอย่างน้อย 3 ข้อ

`/api/chat` ตอบ `MOCK_RESPONSE` เมื่อ `USE_MOCK_AGENT=true` · ถ้า P2 ต้องการ mock แบบอื่น (เช่น `status: "refused"`) ให้เพิ่มโดยเลือกตามคำในคำถาม

### P1-03 · tool `find_values` — 25 ต.ค. · S
**ไฟล์:** `agent/tools.py`
**ทำอย่างไร**
1. ดึงค่าที่ไม่ซ้ำของคอลัมน์: `SELECT DISTINCT "col" FROM "table" LIMIT 1000`
2. ให้คะแนนความใกล้ 3 แบบ แล้วเลือกคะแนนสูงสุด:
   - มีคำค้นอยู่ในค่า (`ILIKE '%คำค้น%'`) → 1.0
   - `jaro_winkler_similarity(ค่า, คำค้น)` ของ DuckDB
   - ตารางคำพ้องเล็ก ๆ ในโค้ด: `{"กทม": "กรุงเทพมหานคร", "โคราช": "นครราชสีมา"}` และตัด "จ." ออกก่อนเทียบ
3. คืน top-k ค่าที่คะแนน ≥ 0.75
4. ตรวจชื่อตารางและคอลัมน์กับ `information_schema` ก่อนใส่ใน SQL (กัน injection)

**เสร็จเมื่อ:** pytest ใหม่ `test_tools.py`: "กทม" ได้ทั้ง 3 แบบสะกดของกรุงเทพฯ, "เชียงใหม่" ได้ "จ.เชียงใหม่"

### P1-04 · tool `make_chart` + timeout ของ query — 26 ต.ค. · S
**ไฟล์:** `agent/tools.py`, `agent/sql_guard.py`
**ทำอย่างไร**
1. `make_chart(type, x, y, columns)`: ตรวจว่า `x` และ `y` อยู่ใน `columns` และ `y` เป็นตัวเลข ถ้าไม่ผ่านคืน `None`
2. กฎเลือกกราฟอัตโนมัติ (ใช้เมื่อ LLM ไม่ระบุ): คอลัมน์แรกเป็นวันที่ → `line`, เป็นข้อความ + ไม่เกิน 12 แถว → `bar`, อื่น ๆ → ไม่วาด
3. timeout: รัน query ใน thread แล้วเรียก `con.interrupt()` เมื่อเกิน 5 วินาที

**เสร็จเมื่อ:** pytest: query ที่วนนาน (`SELECT COUNT(*) FROM range(1e10)`) ถูกตัดใน ≤ 6 วินาที

### P1-05 · agent loop แบบ tool calling — 26–27 ต.ค. · M
**ไฟล์:** `agent/loop.py`, สร้างใหม่ `agent/tool_specs.py`
**ทำอย่างไร**
1. ใน `tool_specs.py` เขียน JSON schema ของ tool ทั้ง 5 ตัว ตามรูปแบบ OpenAI tools
2. loop: ส่ง messages + tools → ถ้า LLM เรียก tool ให้รันแล้วใส่ผลกลับเป็น role `tool` → วนจน LLM ตอบเป็นข้อความ
3. จำกัดสูงสุด 8 รอบ (กันวนไม่จบ)
4. บันทึกทุก tool call ลง `steps` (ชื่อ, args, status, ms)
5. แปลผลสุดท้ายเป็น `ChatResponse` ถ้า LLM บอกว่าต้องถามกลับหรือตอบไม่ได้ ให้ใช้ `status` เป็น `clarify` หรือ `refused`

**เสร็จเมื่อ:** CLI ตอบคำถามที่ต้อง JOIN 2 ตารางได้ และเห็นใน steps ว่าเรียก `describe_table` ก่อน `run_sql`

### P1-06 · eval runner — 28–29 ต.ค. · M
**ไฟล์:** `eval/run.py`
**ทำอย่างไร**
1. `--system A|B|C|D` เลือกระบบ (ใช้ flag ใน loop เช่น `answer(req, system="B")`)
2. ให้คะแนนต่อข้อ:
   - `expect: answer` → รัน `gold_sql` แล้วเทียบผลกับ SQL สุดท้ายของระบบด้วย `results_equal()` (มีอยู่แล้ว)
   - `expect: clarify/refuse` → ถูกเมื่อ `status` ตรง
3. เก็บต่อข้อ: `id, category, correct, status, sql, tokens, ms, retries, error`
4. บันทึก `eval/results/<system>_<YYYYMMDD-HHMM>.json` พร้อมสรุปรายหมวด
5. **รันต่อจากที่ค้างได้** (`--resume <ไฟล์>`) เพราะโควตา LLM อาจหมดกลางทาง
6. หน่วงเวลาระหว่างข้อ (`--sleep 2`) ไม่ให้ชนเพดาน token ต่อนาที

**เสร็จเมื่อ:** รันระบบ A ครบ 100 ข้อ ได้ไฟล์ผล และ**จดจำนวน token เฉลี่ยต่อข้อ** ลง `ISSUES.md` เพื่อวางแผนโควตา

### P2-05 · อัปโหลดไฟล์ → DuckDB — 25 ต.ค. · S (เดิม M)
**ไฟล์:** `routers/datasets.py` · ใช้ `app/ingest.py` ที่**ทำเสร็จแล้ว**

**ที่ทำไว้แล้วใน `ingest.py`** (มี 21 เทสต์ใน `test_ingest.py`)
- รองรับ `.csv .tsv .xlsx .xls .ods .json .jsonl .parquet` (ดู `SUPPORTED_SUFFIXES`)
- เดา encoding ไฟล์ข้อความภาษาไทย: `utf-8-sig` → `cp874` → `tis-620`
- spreadsheet: 1 sheet = 1 ตาราง ข้าม sheet ว่าง · JSON ซ้อน 1 ชั้นแตกเป็นคอลัมน์ `a_b`
- ทำความสะอาดชื่อตาราง/คอลัมน์ (ไทยได้), ชื่อซ้ำ, ชื่อว่าง, ขึ้นต้นด้วยตัวเลข
- จำกัด 10 MB / 20 ตาราง / 200 คอลัมน์ · ไฟล์ปลอมนามสกุล → `IngestError`
- เขียนลงไฟล์ชั่วคราวก่อน แล้วค่อยย้าย — ถ้าพังกลางทางไม่มีไฟล์ครึ่ง ๆ กลาง ๆ

**ที่ต้องทำใน router**
1. ตรวจนามสกุลด้วย `SUPPORTED_SUFFIXES` และขนาดก่อนรับไฟล์ทั้งก้อน
2. บันทึกไฟล์ที่อัปโหลดลง temp โดย**เก็บนามสกุลเดิม** (ingest เลือกตัวอ่านจากนามสกุล)
3. สร้าง `dataset_id` แบบสุ่ม (`ds_` + 12 ตัวอักษร) — **ห้ามใช้ชื่อไฟล์ของผู้ใช้เป็น path**
4. เรียก `ingest(tmp, {DATA_DIR}/datasets/{id}.duckdb)` · จับ `IngestError` → 400 พร้อมข้อความในนั้น (เป็นภาษาไทยอยู่แล้ว)
5. ลบไฟล์ temp เสมอ (ใช้ `try/finally`)
6. บันทึก metadata (ชื่อไฟล์เดิม, `TableInfo` ทุกตาราง) ลงตาราง `datasets` พร้อม `expires_at` = 7 วัน
7. `GET /api/datasets/{id}`: schema + 5 แถวแรก (ตรวจว่าเป็นของผู้ใช้คนนั้น ไม่ใช่ → 404)

**เสร็จเมื่อ:** pytest `test_datasets.py` ผ่าน endpoint จริง: อัปโหลด CSV ไทย 1 ไฟล์, XLSX 2 sheet, `.exe` → 400, ผู้ใช้อื่นเปิดไม่ได้ → 404 · และ **ประสาน P1 (จุดเชื่อม 1, 27 ต.ค.)** ว่า agent อ่านไฟล์ได้
