## 2. โครงสร้างระบบ

```
[Next.js :3000] ──► [FastAPI :8000] ──► [Postgres]  ผู้ใช้, ประวัติแชท, metadata ชุดข้อมูล
                         │
                         ├─► [DuckDB]  ไฟล์ข้อมูลผู้ใช้ (read-only, แยกไฟล์ต่อชุดข้อมูล)
                         └─► [LLM]     Groq ─(ล่ม)─► Gemini ─(ล่ม)─► โหมดพื้นฐาน
```

```
apps/web/              หน้าเว็บ Next.js
services/api/
  app/routers/         auth, datasets, chat
  app/ingest.py        แปลงไฟล์ที่อัปโหลด (8 นามสกุล) เป็น DuckDB
  app/agent/
    sql_guard.py       ตัวตรวจ SQL (อนุญาตเฉพาะ SELECT)
    thai_dates.py      ตัวแปลง พ.ศ./ปีงบ/ไตรมาส/เดือนไทย
    tools.py           เครื่องมือที่ agent เรียกได้
    loop.py            agent loop
    llm.py             เรียก LLM พร้อมสำรองหลายชั้น
  tests/               pytest
eval/                  ชุดคำถาม + eval runner + ผลลัพธ์
scripts/               สร้างข้อมูลตัวอย่าง, smoke test
docs/                  สัญญากลาง, แผน, บันทึกปัญหา
```

### เหตุผลที่ออกแบบแบบนี้

**โค้ดตัดสินเรื่องที่ต้องถูกต้อง ไม่ใช่ LLM**
- ความปลอดภัยของ SQL ตรวจด้วย `sql_guard.py` (แยกวิเคราะห์ด้วย sqlglot) อนุญาตเฉพาะ SELECT และห้ามฟังก์ชันอ่านไฟล์
- การแปลงปีงบประมาณและ พ.ศ. ใช้ `thai_dates.py` ที่ทดสอบด้วย pytest ไม่ให้ LLM คำนวณเอง
- ตัวเลขในคำตอบต้องตรงกับผลลัพธ์ SQL จริง ถ้าไม่ตรงให้ตอบใหม่

**ทุกไฟล์ถูกแปลงเป็น DuckDB ก่อน agent จะเห็น** `ingest.py` เป็นที่เดียวที่อ่านไฟล์ต้นฉบับ รองรับนามสกุลใหม่ได้โดยไม่ต้องแตะ agent และตัวตรวจ SQL ยังบล็อกฟังก์ชันอ่านไฟล์ใน SQL ที่ LLM เขียนได้เหมือนเดิม

**DuckDB สำหรับข้อมูลผู้ใช้** อ่าน CSV/Excel ได้โดยตรง ไม่ต้องตั้ง server แยก เปิดแบบ read-only และปิดการเข้าถึงไฟล์ภายนอก

**ส่งให้ LLM เฉพาะ schema และแถวตัวอย่าง** ไม่ส่งข้อมูลทั้งไฟล์

## 4. รันบนเครื่อง

ต้องมี Docker และ Python 3.12+

```bash
cp .env.example .env      # ใส่ API key
make data                 # สร้างฐานข้อมูลตัวอย่าง data/datasets/demo.duckdb
make up                   # รันทั้งระบบ
make smoke                # ไล่เส้นหลัก
```

เปิด http://localhost:3000 · API docs ที่ http://localhost:8000/docs

ตอนนี้ `USE_MOCK_AGENT=true` เป็นค่าเริ่มต้น `/api/chat` จะตอบด้วยข้อมูลตัวอย่างตามสัญญา

**พัฒนาแยกส่วน (ไม่ใช้ Docker)**
```bash
# API
cd services/api && python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload

# Web
cd apps/web && npm install && npm run dev
```

## 9. ข้อจำกัดและสิ่งที่จะทำต่อ

- รองรับเฉพาะไฟล์ที่มีหัวตารางแถวเดียว
- ยังไม่รองรับ `.pdf` `.docx` และรูปภาพ — ต้องดึงตารางออกจากเอกสารก่อน ซึ่งเป็นอีกโจทย์หนึ่ง
- ยังไม่รองรับ `.sqlite` (ดูงาน P2-15 ใน `docs/TASKS.md`)
- free tier ของ Gemini นำข้อมูลไปใช้ปรับปรุงผลิตภัณฑ์ — **ห้ามอัปโหลดข้อมูลส่วนบุคคล**
